# Schema Evolution Studio

Run `npm install`, then `npm run dev` (Express API on :4174, Vite UI on :4173).
Tests: `npm test`. Typecheck/build: `npm run build`.

## 两种模式

### 单对比较（Single-pair compare）
左侧选择演进场景（新增/删除分支、判别值重用、嵌套 union、默认分支、开放 union…），
中间编辑 v1/v2 两份 JSON 与隐式未知分支策略，右侧独立展示**向后**与**向前**
两个方向的判定，失败时可展开经两侧验证器证明的最小反例。判定全部来自
`src/shared/compat.ts`，方向缓存键带方向与策略（`src/server/compat.ts`）。

### 多消费方发布（Multi-consumer release）
一份待发布的生产者定义面对一组**各自独立演进**的具名消费方（甲旧封闭定义、
乙中间定义、丙只处理开放 union）。回答的是"这次部署，每个在位消费方能否读取
新生产者的数据"（只取向后方向），准入规则是：**预览时被标记为必需的每个
消费方都通过**；非必需消费方即使拒绝也只显示为风险，不改变准入。

状态一致性由服务端保证，浏览器不能自我授权：

- `GET/POST/PUT/DELETE /api/release/consumers` — 消费方是带**修订号**的具名
  实体；PUT 需要 `expectedRevision` 做乐观并发（他人先改则 409 并返回当前定义），
  任何定义/必需标记变更都产生新修订。
- `POST /api/release/preview` — 服务端用与单对比较**同一个引擎**逐消费方计算，
  返回每个消费方各自的方向性判定、拒绝原因和验证器反例，并把**消费方修订集合 +
  生产者定义哈希**钉在一个不透明令牌上。
- `POST /api/release/releases` — 只需令牌。服务端重新核对：自预览后无消费方
  修订移动（含新增/删除），否则 `409 stale_preview`（附带按当前名册重算的
  `fresh`，但不能直接批准，必须显式重新预览）；再在服务端**重跑**准入闸门，
  失败为 `422 gate_blocked`；全部通过才持久化发布记录并返回。令牌一次性。
- `GET /api/release/releases(/:id)` — 发布记录保存当时的**生产者定义原文**、
  每个消费方的修订/哈希/必需与否/判定/拒绝原因和预览令牌；重新打开页面看到的
  是服务端确认过的决定，而非浏览器最后一次计算的结果。

页面上：草稿本地修改、轮询发现名册修订移动、或确认被服务端判为过期，都会立即
把预览标记为失效并禁用确认按钮；服务端确认返回记录后界面才显示"已发布"。
